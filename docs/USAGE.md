# 使用与兼容说明

## 模块与框架

Pixel MiPushFramework 提供共享推送服务，接收消息并按规则生成通知。Pixel MiPush 模块提供设备识别与系统通知增强，需要 Root 和支持 Xposed API 102 的 LSPosed。

先完成框架初始化，再启用模块及作用域。推送服务通常使用 `normal` 版本，只有接入方明确需要旧服务版本范围时，才选择 `vc105`。

模块的独立选项位于框架「设置 → 模块设置 → QQ 通知定制」。QQ 作为一个个性化项目统计，角标、会话头像和汇总简化分别控制。修改后可查看设置同步状态，具体含义见 [模块控制说明](MODULE-CONTROL.md)。

## 旧包迁移

历史 Pixel 模块包名为 `com.neko7ina.mipush.pixel`，现用包名为 `com.neko7ina.pixelmipush`。新包作为独立模块安装，作用域和模块私有配置需重新设置。

1. 在 LSPosed 中关闭旧模块，保持同一作用域只启用一个 MiPush 模块版本。
2. 安装新模块并启用，重新选择系统框架、系统界面、推送服务和所需目标应用。
3. 按需恢复模块私有配置，然后重启设备。
4. 检查框架内的模块状态，再测试目标应用注册、真实消息和通知样式。
5. 确认新模块工作正常后，再自行决定是否移除旧包。

框架和通知规则目录继续使用原位置。同包名更新以签名一致为前提，使用本项目正式版的用户可覆盖安装后续正式版本。

## 通知规则

通知标题、渠道、会话样式、头像、点击行为和分组由框架规则决定。可从 [MiPushConfigurations](https://github.com/NihilityT/MiPushConfigurations) 按需选择配置，先阅读文件说明，互斥的白名单、黑名单或样式文件只选一套。

QQ 在 Pixel 上的既有配置组合为：

- `com.tencent.mobileqq_QQ.json`
- `com.tencent.mobileqq_QQ_MessagingStyle.json`
- `com.tencent.mobileqq_QQ_意图重整.json`
- `2_后置配置_直接打开意图-白名单.json`，并将 `com.tencent.mobileqq` 加入白名单

「直接打开意图」让新通知使用直接打开页面的点击方式，用于处理通过推送服务间接打开 QQ 时的系统界面动画超时。配置变更影响之后创建的新通知，请使用新消息对照效果。

模块保留通知中的联系人和群头像，角标图标由框架生成。会话头像布局用于调整 Pixel 的会话通知模板，具体尺寸与生效条件见 [技术说明](../PIXEL-API102.md)。

## 兼容与排查

本项目主要适配 Pixel 的 Android 16 和 Android 17。通知样式依赖系统内部实现，系统更新或其他厂商模板需要重新核对，历史验证结果见 [技术说明](../PIXEL-API102.md) 和 [开发记录](STATUS.md)。

### 模块未就绪

检查 LSPosed 中是否已启用模块，以及系统框架、系统界面和推送服务作用域是否完整。安装或更新模块后重启设备，再到框架的模块设置页查看加载与同步状态。

### 应用接收不到消息

先确认框架连接正常，目标应用已完成小米推送注册。为需要设备识别适配的应用启用作用域后，重新打开该应用并检查注册结果。

应用自身决定是否提供小米推送接入，QQ 服务端也会决定何时转为厂商推送。请用真实消息测试，并在框架中核对接收和处理记录，区分接入、消息送达和通知显示问题。

保持框架、LSPosed 及相关应用所需的后台运行和网络权限。冻结推送服务或限制其网络会影响消息接收。

### QQ 通知样式没有变化

先确认收到的是由框架处理的 QQ 会话通知，规则已生成对应的头像、会话样式和图标。再检查系统界面作用域与模块状态，并用新生成的通知对照设置。

汇总副标题清理只针对 QQ 分组汇总通知，普通子通知保持自身副标题。当前 Android 17 样本中，关闭简化后也未出现重复 QQ 文案，原因仍待研究，不能据此推断所有系统都已替代这项处理。

## 源码构建

使用 JDK 17、Android SDK 34 和仓库 Gradle Wrapper。从仓库根目录构建模块：

```bash
./gradlew :app:assembleRelease
```

也可在 GitHub 的「Actions → Build installable APK → Run workflow」选择开发分支，按需填写 `version_name` 和 `version_code`，生成开发构建产物。

自行构建包与正式版的签名可能不同，覆盖安装前需核对证书。正式发布的签名、版本和附件校验沿用 [发布约定](RELEASING.md)。
